# Live Sanity E2E

## Purpose

This note records live Somnia sanity checks after the evidence-generation
hardening work. The goal was to distinguish invalid legacy UI evidence from
contract or live-agent failures, then prove the current verified real-data
evidence path with fresh Escrow and GrantRound flows.

No deployed contracts were modified. No private keys or `.env` values are
included here.

verdict:

`Incomplete -> contractor resubmits improved evidence -> verification runs again -> Complete -> claim`

Retry was intentionally not used. `retryVerification` reuses the same stored
evidence and is appropriate for transient agent/API failures on otherwise valid
stored evidence. For `Incomplete`, the work/evidence was evaluated but found

- Retry should be reserved mainly for transient agent/API failures on otherwise
  valid stored evidence.

## UI Copy Recommendation

For `VerificationFailed`, show copy that distinguishes retrying infrastructure
failures from resubmitting corrected evidence:

> Verification failed before a work-quality verdict was produced. Retry charges
> the same verification fee and reuses the currently stored evidence. Retry only
> if the agent or API failed temporarily. If the evidence is malformed,
> unreachable, or invalid, submit revised evidence instead.

For Escrow TwoAgent retry, show the required retry deposit explicitly:

> Retry fee: 0.36 STT. This retries the same evidence URI and does not fix bad
> evidence.

For malformed evidence, prefer a stronger callout:

> Current evidence appears invalid or unreachable. Submit revised evidence before
> retrying verification.

## Limitations

- This is a live smoke/proof workflow, not deterministic CI.
- Local Foundry script simulations sometimes show `NotActivated` when reading
  the Somnia platform deposit, while the broadcast path succeeds with the known
  workflow deposit.
- Direct `cast tx` / `cast receipt` still hit a local transport issue in this
  environment; raw JSON-RPC via `curl` was used for bounded receipt and log
  inspection.
- The Escrow run proved the validated-evidence path does not fail closed on
  malformed fields, but the live LLM returned `Incomplete`. It should not be
  documented as a Complete/Claimed proof.
